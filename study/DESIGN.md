# 实验设计的统计原理

本文只写**为什么这样设计才推得出东西**。跑什么、判什么、词表是什么见 [README.md](README.md)，不可破坏的约束见 [../docs/ARCHITECTURE.md](../docs/ARCHITECTURE.md)。

## 1. 估计量：先把要估的东西定死

**研究问题**：一个没有任何人要求它注意的环境线索（工作目录名里的词），会不会移动 agent 选择哪个分析运行时。

要估的量（下称估计量）：

| 记号 | 定义 |
|---|---|
| 处理 | 槽位名里的词：中性词 / 指向 R 的词 / 指向 Python 的词 |
| 结局 `Y` | 该 trial 里**第一个**说出运行时的工具调用是哪个运行时；取 `R` / `Python` / `shell`（只在 shell 里算，没动用运行时）/ `none`（一个工具都没调用） |
| 主对比 | `Δ_R = P(Y=R | R 语词) − P(Y=R | 中性)` |
| 主对比 | `Δ_P = P(Y=Python | Python 语词) − P(Y=Python | 中性)` |

两条都是**单侧**的、**各自对同一中性基线**的对比。

## 2. 三个不要做的事

这一节是本文最重要的部分，三条都是"看起来合理、实际上把因果推断做废了"。

### 2.1 不做 cue 对 cue 的对比

`Δ_R` 与 `Δ_P` 乍看可以合成一个"哪个语词更强"的对比。不行：一个在**克服赤字**（R 在语料里本就不占优），一个在**强化默认**（Python 本就是默认）。两者的可用空间不同，效应量不可比。能比的是归一化之后的量（第 4 节），而那也只是描述性的。

### 2.2 主分析不按"是否动用了运行时"分层

把结局限定成 `Y ∈ {R, Python}`（即剔除 `shell` 与 `none`）是**对处理后变量取条件**。语词完全可能通过"让模型更愿意动手算"来影响结局；一旦按"有没有动手"分层，这条路就被切断了，而且引入选择偏倚（两层的人口构成不同）。

所以主分析用**无条件的** `P(Y=R)`。`shell` 与 `none` 都算作"不是 R"，它们是合法的结局取值，不是要被剔除的坏数据。

这不是洁癖——它改变结论的适用范围。条件版本回答的是"已经在两种运行时里选的时候选哪个"，无条件版本回答的是"这个语词把选择挪动了多少"，后者才是研究问题。

### 2.3 不用准确率当主结局

题目有六个连续量、有 NIST 认证值，准确率确实有梯度。但准确率测的是**算得对不对**，不是**语言偏好**；而且它会被算法选择污染（R 的 `lm` 用 QR，手写的正规方程未必一样稳）。它只能当次级结局。

## 3. 语料先验：不是偏倚，是量程受限

"Python 训练语料远多于 R"是这件事里最容易被误判的干扰。要分清两种东西：

| | 是否随处理变化 | 后果 | 能不能靠分析消除 |
|---|---|---|---|
| 混杂（bias） | 是 | 对比本身偏了 | 靠设计或校正 |
| 量程受限（restriction of range） | 否 | 效应上限被压低 | **不能**，只能如实报告 |

随机化之后模型的语料先验是个常数，各臂受同样影响，所以它**不产生偏倚**。它限制的是**天花板**：若中性臂 `P(Python)=0.64`，那么 Python 语词最多只能再抬 `1−0.64=0.36`。

后果有两层：

1. **两臂的效应量不可直接比较**，必须归一化。
2. **贴着天花板的那一臂，看起来"没反应"可能只是没空间了**，不能读成"该语词无效"。这一条是反面解读里最常见的错误。

### 归一化怎么读

```
δ_R = Δ_R / (1 − P(Y=R | 中性))
δ_P = Δ_P / (1 − P(Y=Python | 中性))
```

`δ` 读作"吃掉了多少可用余量"。若 `δ_R ≈ δ_P`，说明语词的作用是按可用空间成比例分配的，语料先验只是个尺度因子；若差得远，说明两件事之一——某一侧的语词特别有效，或另一侧被天花板压住了。**这两个解释单靠一个模型的单批数据分不开**（第 7 节）。

`δ` 是描述量。推断仍在原始尺度上做，或换到 log-odds 尺度（它在接近 0/1 时不受压缩）。但 log-odds 在 `P=0` 或 `1` 处发散，地板基线必须做连续性校正——**校正值（例如 Haldane–Anscombe 的 +0.5）必须预声明**，不能事后挑一个顺眼的。

## 4. 为什么守地板比抬到中间更省试次

直觉说"让 R 变得自然，把基线从 0 抬到中间，语词就有活动空间了"。方向感对，算术是反的。

同样 +0.3 的绝对抬升，k=7 每臂：

| 中性基线 | 语词后的率 | 检出功效 |
|---|---|---|
| **0%** | 30% | **0.35** |
| 20% | 50% | 0.23 |
| 50% | 80% | 0.21 |

原因很朴素：从 0 出发，语词臂里出现 3 个 R 就已经很反常；从 50% 出发，得跑到 10/14 才算反常，而那要求语词几乎百分之百有效。达到功效 0.8、+0.3 抬升所需：基线 0% → k≈28；基线 20% → k≈40。

**地板的代价**：只能测"语词让它变多"，测不了"变少"；且 log-odds 不可用（见上）。

### 但基线不能用来选题

这是本节的关键约束。既然地板更便宜，就有强烈的动机去挑一个基线贴地的题目——**那就是先看结局再出题**，p 值随即失去意义（forking paths）。

所以：

- 题目按**与结局无关**的标准选（第 6 节）。
- 基线是**报告对象**，不是**选择对象**。
- 探针试次只用来定 k，并预声明不进最终分析。

## 5. 措辞是随机效应

一个条件只有一个字符串（`tidyverse`），7 次重复只是同一个词重复 7 次。这时结论只能是：

> "`tidyverse` 这个词把 R 从 0 抬到 29%"

而不能是：

> "提到 R 生态会让 agent 偏向 R"

这既是推广性问题，也是 4 节末尾那个陷阱最隐蔽的形式：如果因为那个词看着有戏就继续用它，就是在挑一个奏效的词。

做法：每个条件用 3–4 个**语义等价、字面不同**的槽位名，把措辞当 block（更理想是随机效应）。结论才针对类别。代价是试次数乘以措辞数——它买的是推广性，不是精度。

## 6. 题目怎么选（合法标准）

只许用四条与结局无关的标准：

1. **题源在外部**——教材、公开基准、别人出的分析问题。题目不是自己编的，就没有编题的自由。
2. **两种语言能力对等**——自己各写一遍验证，不涉及受试体。
3. **单一确定真值**——不含随机数（R 与 Python 的 RNG 不同，答案就不唯一）、不依赖库版本默认值（分位数类型、加权 sd、对照编码都要钉死）。
4. **任务本身是真实分析师会做的**，不是为实验造的怪题。

基线落在哪，测出来报告，不用来挑。

## 7. 容差怎么从"几位有效数字"推出来

题目要求"保留 k 位有效数字"，容差就不能拍一个数。**同一个 k，相对误差取决于尾数位置**：`1.00212` 舍到 6 位丢 3.2e-6，`0.999994` 舍到 6 位只丢 2.5e-7。统一阈值要么冤枉前者，要么放过后者。

规则（逐字段）：

```
ε_k  = 把认证值舍到 k   位有效数字产生的相对误差
ε_k1 = 把认证值舍到 k−1 位有效数字产生的相对误差
容差 = sqrt(ε_k · ε_k1)        # 几何中点
```

只要 `ε_k < 容差 < ε_k1`，正确舍到 k 位的答案必过、k−1 位的必拒。可以逐字段验证。

`study/criteria/v1.json` 对 Welch p 值用的就是这个方法的单字段版本；Norris 六个字段是同一方法的多字段版本。**这套推导要写进依据（`tolerance_notes`），不能只留数字。**

## 8. 威胁清单与对策

| 威胁 | 为什么是威胁 | 对策 | 能不能彻底解决 |
|---|---|---|---|
| 操作者路径泄漏 | 会话根目录名里的词会随注入到达每个 trial | 窗口补丁 + `exposure_check` 闸门 | 能（窗口关闭后逐字节还原） |
| 顺序效应 | 臂与位置共线 | 按重复交错；`order` 进 plan | 能 |
| 交付字节不一致 | 手打多份 schema，键序漂移；我们的规范哈希看不见 | 用宿主 `toolSchemaDigest` 断言单值 | 能 |
| 数值条件 | 病态数据让不同算法给出不同结果 | 先测条件数，确认 k 位安全 | 能（Norris `cond(X'X)=7.3e5`，6 位安全） |
| 措辞选择 | 结论只针对一个词 | 多措辞 + block | 部分（需更多试次） |
| 记忆直出 | 认证值公开，模型可能不碰工具 | 见下：作为**结局**报告，不作为剔除理由 | 部分 |
| 语料先验 | 限制效应上限 | 归一化 + 跨模型复制 | **不能**（单模型内部无法分离） |
| persona 与实际要求不符 | harness 的 persona 写"报 4 位有效数字"，题面要求 6 位；这是第三个未声明的变量 | 报告实测：288 条全部按 6 位作答，判定不受影响（282 通过，6 条散文作答与位数无关）。**不改**——改它换 `systemPrompt` 摘要，这 288 条就成了另一个条件 | 不是威胁，是登记在案的常量 |

### 记忆直出的正确处置

认证值公开，模型可能凭记忆直出而不碰工具。处置方式**不是**"把零调用试次剔掉"——那是 2.2 说的同一种错误（对处理后变量取条件）。

正确做法：

- 零调用算作 `Y=none`，在**主分析里保留**，取值"不是 R"。
- **零调用率本身是一个次级结局**，分臂报告——它可能正是语词效应的一个表现。
- 预声明一条**仪器有效性规则**：若零调用率超过预设阈值（例如 1/3），则判定该题目对本题不可用，换数据集重跑，该批只作探索。这条规则的作用对象是**题目**，不是**试次**。

## 9. 预注册：`plan_id` 就是承诺

```
plan_id = sha(臂表 + 题面 + schema + 执行顺序)
```

改题、改臂、改顺序，`plan_id` 就变。所以只要**跑之前提交 plan**，"事后改题"在 git 历史里留下两个不同的 id，无法悄悄发生。

纪律三条：

1. plan 先提交，再开跑。
2. 探针只定 k，预声明不进最终分析。
3. 口径变了就换 `criteria_id`／新 plan，不原地改旧结论。

## 10. 现在承认的局限

- **跨模型复制缺失。** 语料先验是模型的属性，只有换一个语料构成不同的模型，才能把"先验"和"语词"分开。本机只有一个路由，所以这条记为必须处理事项，不记为已解决。
- **措辞若只用一两个，结论不可推广到类别。**
- **地板基线只能测单方向**，且 log-odds 需要预声明的连续性校正。
- **persona 的位数要求与题面不一致，且已冻结。** `assay-neutral.yml` 写"报 4 位有效数字"，`tasks/norris-ols.json` 要 6 位。两者都是系统提示词的一部分，所以任何修正都会改 `systemPrompt` 摘要，让已跑的 288 条变成另一个条件。实测它没有造成差异（全部按 6 位作答），所以选择保留矛盾并登记，而不是重跑。下一个 `plan_id` 应当对齐这两处。
